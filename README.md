# متجر مناحل انيس بن دحمان

متجر إلكتروني لبيع ملكات النحل (عذراء وملقحة) في الجزائر: React + TypeScript + Tailwind + Supabase (PostgreSQL، المصادقة، التخزين).

## 1) إنشاء مشروع Supabase
1. أنشئ مشروعًا على supabase.com.
2. من **SQL Editor** شغّل بالترتيب: `supabase/migrations/001_schema.sql` ثم `supabase/migrations/002_seed.sql` (مرة واحدة فقط).
3. من **Authentication → Providers → Email** عطّل التسجيل العام (Allow new users to sign up) لأن المتجر لا يحتاج حسابات عملاء.

## 2) إنشاء حساب المسؤول
1. **Authentication → Users → Add user**: أدخل بريدك وكلمة مرور قوية (فعّل Auto Confirm).
2. شغّل في SQL Editor (بدّل البريد ببريدك):
```sql
update public.profiles set role = 'admin'
where id = (select id from auth.users where email = 'you@example.com');
```
3. ادخل إلى `/admin` من الموقع. لا أحد يستطيع ترقية نفسه إلى مسؤول من الواجهة.

## 3) التشغيل محليًا
```bash
cp .env.example .env.local     # ضع VITE_SUPABASE_URL و VITE_SUPABASE_ANON_KEY من Settings → API
npm install
npm run dev
```
لا تضع مفتاح `service_role` في الواجهة أبدًا. مفتاح `anon` عام بطبيعته، والحماية تأتي من سياسات RLS والدوال في قاعدة البيانات.

## 4) النشر
- **Vercel / Netlify / Cloudflare Pages**: Build command `npm run build`، Output `dist`. ملفا `vercel.json` و`public/_redirects` يضمنان عمل المسارات.
- أضف متغيرات البيئة الثلاثة: `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` و`SITE_URL` (رابط الموقع النهائي لتوليد `sitemap.xml` عند كل بناء). أعد النشر بعد إضافة منتجات جديدة لتحديث الخريطة.

## 5) أول إعداد من لوحة التحكم
1. **إعدادات المتجر**: الشعار، اللون، أرقام الهاتف وواتساب، التواصل الاجتماعي، السياسات، طرق الدفع (تعليمات CCP/البنك قبل تفعيلها).
2. **الولايات والتوصيل**: كل الولايات (69) معطّلة مبدئيًا. فعّل ما تستطيع الإرسال إليه وحدّد سعر كل طريقة ومدتها.
3. **المنتجات والمخزون**: أضف منتجًا، ارفع صوره، ثم أضف دفعة (الكمية، التواريخ، الحجز المسبق والعربون إن وُجد).
4. **المحتوى**: عدّل نصوص الصفحة الرئيسية والأسئلة الشائعة والمقالات.

## كيف يعمل المخزون
- كل دفعة: `available = total - reserved - sold - manual_reserved`، وقيد في القاعدة يمنع تجاوز المجموع.
- إنشاء الطلب (`place_order`) يقفل الدفعة ويتحقق ويحجز في عملية واحدة، فلا يمكن البيع الزائد حتى مع طلبات متزامنة.
- الأسعار والتوصيل والخصم تُحسب في الخادم فقط؛ ما يرسله المتصفح من أسعار يُتجاهل.
- حالات الطلب: جديد / بانتظار العميل / مؤكد / قيد التحضير ← **محجوز**؛ تم الشحن / تم التسليم ← **مباع**؛ ملغى / تعذر التسليم ← **تُعاد الكمية**. التحويل يتم مرة واحدة فقط مهما كرّرت تغيير الحالة.
- يتتبع العميل طلبه من `/track` برقم الطلب + رقم الهاتف دون حساب.

## الدفع
المفعّل: الدفع عند الاستلام، والتحويل البريدي/البنكي بالتعليمات التي تكتبها. **الدفع الإلكتروني غير مدمج**: يلزم مزوّد يدعم الجزائر، حساب تاجر، دمج واجهته واختباره قبل تفعيله.

## ملاحظات
- ملفات SQL غير قابلة لإعادة التشغيل بالكامل (سياسات RLS تُنشأ مرة واحدة). لإعادة البدء أنشئ مشروعًا جديدًا أو احذف الجداول أولًا.
- الصور تُرفع إلى Supabase Storage (حاوية `store-media`) وتُضغط في المتصفح قبل الرفع.
